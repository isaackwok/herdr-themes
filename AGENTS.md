# AGENTS.md

This repo holds themes for the Herdr app. Each top-level directory is one theme.
Its files are laid out the way they go in Herdr's home, `~/.config/herdr-app/`
(called `$H` below). `CLAUDE.md` is a symlink to this file.

Before you change any Herdr files, read Herdr's own reference at
`$H/AGENTS.md`, especially the sections "Layouts and mods other people made",
"Keys", and "Check before you finish". If it disagrees with this file, follow
Herdr's reference.

**Each theme directory has its own `AGENTS.md`. Read it before you install or
edit that theme.** It gives the theme's name, what its mod runs on the
person's machine, and anything specific to that theme. This file covers only
the rules that apply to every theme.

## Theme index

| Directory | Name (layout = theme = mod) |
| --- | --- |
| `rpg/` | `herdr-quest` |

Inside a theme directory, `mods/`, `layouts/` and `themes/` map straight to
`$H`. The theme's `keys.json` is the exception: you **merge** it into
`$H/keys.json`. Never copy it over that file.

## Installing a theme (do these in order)

Use `./herdr-theme install <theme>` and `./herdr-theme uninstall <theme>` at the
repo root. The script handles steps 2–5 below. It refuses to touch clashing
files or rebind keys you've already bound unless given `--force`, backs up
`keys.json` before changing it, runs `herdr-app check`, and switches the
layout. Start with `--dry-run`. Only pass `--force` after the person agrees.
Step 1 is always yours to do. The manual steps below show what the script
does, for when you can't run it.

1. **Tell the person what the mod does on their machine before you copy
   anything.** The theme's `AGENTS.md` lists it. Still grep the mod for
   `exec(`, `hc(` and file reads, in case that list is out of date.
2. **Check for name clashes. Never overwrite anything.** Look for
   `$H/mods/<name>`, `$H/layouts/<name>.json` and `$H/themes/<name>.json`.
   If one exists, ask the person. Either they want to update it in place, or
   you rename the new copy everywhere: the folder and file names, every
   `"mod": "<name>"` and `"theme": "<name>"` in the layout, `"preview"`,
   `<name>.` prefixes in `keys.json` actions, and any `mods/<name>/` paths
   inside the mod.
3. **Copy the files:**
   ```sh
   cp -R <theme>/mods/*    $H/mods/
   cp    <theme>/layouts/* $H/layouts/
   cp    <theme>/themes/*  $H/themes/      # if the theme has a themes/ dir
   ```
4. **Merge the keybindings.** Make a backup first. If a key in the new
   `layout:<name>` section is already bound in that same section of the
   person's file, ask before replacing it.
   ```sh
   cp $H/keys.json $H/keys.json.bak
   jq -s '.[0] * .[1]' $H/keys.json.bak <theme>/keys.json > $H/keys.json
   ```
5. **Verify:**
   ```sh
   herdr-app check $H/mods/<name>             # must print "check passed"
   herdr-app do layout.switch --name <name>
   herdr-app status                           # look for errors from files and mods
   ```
   Also check that no `$H/*.error` file appeared (for example `layout.error`
   or `keys.error`). The installed theme is not finished until the check
   passes and the status shows no errors.
6. **Tell the person how to undo it:** `ctrl-shift-l` cycles back to their
   previous layout, `ctrl-alt-shift-escape` resets to `main`, and the theme's
   README has the uninstall commands.

You can't script real keypresses. If something depends on keyboard focus, ask
the person to try it.

## Working on this repo

- The live copy in `$H` is the source of truth while you develop. Edit and test
  there, then sync into the repo:
  ```sh
  rsync -a --delete --exclude gpui-kit.d.ts $H/mods/<name>/ <theme>/mods/<name>/
  cp $H/layouts/<name>.{json,svg} <theme>/layouts/
  cp $H/themes/<name>.json        <theme>/themes/
  ```
  To get just this theme's keys section:
  `jq '{"layout:<name>": ."layout:<name>"}' $H/keys.json > <theme>/keys.json`.
- Never commit these:
  - `gpui-kit.d.ts`: generated by Herdr and gitignored
  - `$H/data/<mod>/`: the person's saved state
  - any file containing absolute paths, usernames or tokens

  Grep for `/Users/` before every commit.
- A theme's `RECIPE.md` describes what the theme really does (Herdr's format;
  see "Layouts and mods other people made" in `$H/AGENTS.md`). When you change
  a theme's look or behavior, update its recipe in the same commit.
- Run `herdr-app check <theme>/mods/<name>` on the repo copy before you
  commit. It works from any path.
- When you change `herdr-theme`, test it against a throwaway home:
  `HERDR_APP_HOME=$(mktemp -d) ./herdr-theme install <theme> --no-switch`,
  then `uninstall`. Never test it against the real `$H` without
  `--dry-run`.
- To add a theme: create a new top-level directory with the same structure,
  use a single name that doesn't clash with Herdr's shipped mods and layouts
  (`ls $H/mods $H/layouts`), give it its own `README.md` and `AGENTS.md`
  (model them on `rpg/`), and add a row to the index above and to the
  Themes table in `README.md`.
- Commits to this repo use the person's personal GitHub account. The remote is
  `git@github-personal:isaackwok/herdr-themes.git`; keep it.
